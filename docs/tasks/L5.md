## 2. XUI2D 後端（新檔 `Module/Render/FullscreenXUI2D.h/.cpp`，只在 `CEV_HAVE_XUI2D` 下編入）

XUI2D 不是保留式：有圖層的每一幀都要送。資料來源與 `XUI2DL` 後端完全相同（L4 的 `SLayer`／`SDebugLayer` 與目的矩形的換算——把換算抽成兩個後端共用的一段，產出「後端無關的四邊形清單」：種類、目的矩形、貼圖 id、混合、顏色、平面描述）。

- **表面**：第一次有圖層時 `CreateScreenSurface(無效的 SDisplayContextKey)`（= 主視窗；以 `IXUIRenderer.h` 的說明為準），`SetSurfaceOrder(id, -(1 << 20))`，viewport 設為整個輸出（輸出大小改變時重設）。沒有圖層的幀不送任何東西（先讀 XUI2D 的程式確認「某一幀沒有 Submit」時該表面是否就不畫；不是的話停下回報）。`Shutdown` 與資源世代改變時銷毀／重建。
- **提交時機**：必須在 `UpdateBeforeRender`（播放器 tick 與貼圖上傳之後）提交，才會與 CryXTUI 的幀落在同一批、照 order 排在 UI 之下（XTFrame 主線的讀碼結論：`xui2d_afterScene` 開啟時，之後才提交的會畫在 UI 之上）。做法：`FullscreenOutput::Present` 增加一個參數說明是哪個步驟（BeforeRender／AfterRender）；`XUI2D` 後端只在 BeforeRender 送、`XUI2DL` 後端照舊只在 AfterRender 送。`cev_probe_sync` 的 B 方塊在 `XUI2D` 後端下取不到 AfterRender 的序號——改用 BeforeRender 的序號並在說明字串與每秒的標籤 log 註明。
- **幀內容**：一個 target 0 的 `SPass`（不清除）；每個四邊形 4 個 `SVertex`＋6 個索引、一個 `SDrawCmd`：純色 → `EShading::Solid`；RGBA（預乘）→ `EShading::Texture`；打包 → `EShading::TexturePlanar`，`paramIndex` 指向 48 個 float 的 `SPlanarParams`。混合：黑邊 `Replace`，其餘 `SrcOver`。取樣器 `LinearClamp`。座標是輸出像素、原點左上；貼圖第 0 列是頂列（`u,v` 由 (0,0) 到 (1,1)）。頂點色為預乘的 (1,1,1,1)（純色時為該顏色）。`SFrame`、`SPass`、`SDrawCmd` 其餘欄位的填法以 `IXUIRenderer.h` 的註解與 CryXTUI 的實際用法（`Code/CryPlugins/CryXTUI/` 內提交 frame 的程式，唯讀）為準；裁切欄位「不裁切」的寫法照 XUI2D 的實作確認。
- **`SPlanarParams`**：在插件端計算（新的檔內函式），規則是 XTFrame 倉 `Docs/design/23-host-integration.md` §23.aj「繪製」一節與 `IXUIRenderer.h:106-113, 369-377` 的註解：每平面的 uv 縮放位移（色度位置折進 U／V 的位移）、箝制矩形（平面矩形內縮半個 texel）、3×4 矩陣、`hasAlpha`、`premultiplied = 0`。平面矩形、矩陣、範圍、siting 取自 `SLayer`；貼圖尺寸取自引擎貼圖。
- **貼圖句柄**：`WrapEngineTexture(engineTextureId)`，每個引擎貼圖 id 快取一個句柄；`GetResourceGeneration()` 改變時全部作廢重取；貼圖不再被任何圖層使用且寬限期過後銷毀句柄（用介面上對應的銷毀函式）。
- **貼圖生命（重要）**：XUI2D 對包裝的引擎貼圖**不持有引用**，渲染執行緒是在繪製時才以 id 查貼圖，而引擎的貼圖 id 會重用。所以後端自己對「最近送出的幀用到的每張貼圖」持有一個 `_smart_ptr<ITexture>`，在最後一次引用它的提交之後再保留 **4 個主執行緒幀**才釋放。播放器銷毀、排列切換（RGBA ↔ 打包會重建貼圖）都靠這個機制安全過渡。
