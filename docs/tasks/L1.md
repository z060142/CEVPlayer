## 實作要求（規格 §5 的落實）

1. `SetFrame`（主執行緒，非主執行緒呼叫 → 回 0）：檢查 `size`、`layerCount ≤ 16`、`kind`／`blend` 合法；以 `CTexture::GetByID` 取貼圖並持有 `_smart_ptr<CTexture>`。先以原始碼確認在主執行緒取得並持有 `CTexture` 引用是安全的（引用計數的實作、`GetByID` 的鎖）；不安全就停下回報。`GetByID` 找不到時引擎回的是「NoTexture」佔位貼圖而不是空指標（調查 E）：這種圖層視為沒有貼圖，略過並計入 `drawsSkipped`。
2. 快照不可變、引用計數；主執行緒只做指標交換。最後一個引用的釋放不得發生在 render loading thread（照 `XUI2DRenderer.cpp:2505-2527` 的延後做法）。
3. `EndFrame`：目前快照非空且資源存在時排渲染命令；空快照不排任何命令。
4. 渲染執行緒：輸出與 viewport 的取得照 `XUI2DPass.cpp:654-682`；幾何一次上傳，之後重設命令列表（`XUI2DPass.cpp:448-460`）；每個圖層一個 primitive；scissor 與前一個不同就另開 instance（`XUI2DPass.cpp:1360-1381`）；混合狀態照 `XUI2DPass.cpp:54-67`；PSO 未就緒 → 略過並計數。
5. `RT_CreateResources`／`RT_ReleaseResources`：照調查 E；釋放時丟掉目前快照。著色器預熱照調查 C.1，但不做「第一幀阻塞等待」，未就緒就略過。
6. 不新增 cvar。log 只在建立／釋放資源、著色器找不到、每 300 幀一次的略過統計。
7. 不使用任何 D3D11 專屬型別以外的後端專屬程式（頂點宣告結構除外，見調查 B）。
