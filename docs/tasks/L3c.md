## 1. 引擎端（`EnginePatch/`）

### 1.1 卸關卡不得丟掉保留快照（L3b 的問題 A）

現況：`XUI2DL::RT_ReleaseResources()` 同時丟掉保留快照與渲染資源；卸關卡的 `FreeSystemResources(FRR_SYSTEM_RESOURCES)` 會走到它，於是第二次以後的讀取迴圈不畫、讀取結束後全螢幕影片也不回來。

裁決：**保留快照是呼叫端的狀態，不是渲染資源**。拆成兩件事：

- 渲染資源（著色器、緩衝、pass、primitive）：照現況在 `RT_ReleaseResources` 釋放，之後照既有的延後建立與 §1.2 的預熱重建。
- 保留快照：只在渲染器真正關閉時丟掉（裝置銷毀／渲染器 shutdown 的路徑），卸關卡時保留。

動手前先讀引擎：`FreeSystemResources` 各旗標對貼圖做什麼、我方掛點在哪些旗標下被呼叫、有沒有任何路徑會在快照仍持有 `_smart_ptr<CTexture>` 時強制釋放那張貼圖的裝置資源。**若卸關卡的路徑會讓快照持有的貼圖失效（裝置貼圖被釋放而 `CTexture` 物件還在），停下回報，不自行設計**。`M11-xui2dl.md` §5 對應的那一句照實改寫（這張單允許改這一句與 §9）。

`s_deviceAvailable` 在釋放與重建之間為假的期間，主路徑與迴圈照現況不畫。

### 1.2 預熱要等到真的能畫（L3b 的問題 B）

現況：`LoadtimePrewarm` 只等著色器實例就緒；沒有著色器快取時 pipeline state 在迴圈內一直建不起來，迴圈每圈在 `AddPrimitive` 失敗（跳過 315 次），也沒有那一行 log。

裁決：

- 預熱的就緒條件改為「目前快照會用到的每一種技法，其 primitive 都能成功編譯（與主路徑繪製時相同的編譯呼叫回報成功）」。在渲染執行緒做，最多等 2 秒（現有的迴圈與 10 ms 間隔不變）。
- 逾時：記現有那一行 log，並設一個「本次讀取迴圈不畫」的旗標；`RT_LoadtimeRender` 看到旗標就直接返回（不再每圈嘗試、不累加 `drawsSkipped`）。旗標在迴圈結束時清除。
- 預熱成功後迴圈內仍遇到繪製失敗（不該發生）：第一次記一行 log，之後照現況計入 `drawsSkipped`。
- 先讀引擎確認 2 秒內做得到的機制：沒有著色器快取時，pipeline state 的建立卡在哪（非同步著色器編譯的結果要由誰在哪個執行緒收取）。預熱在主執行緒等待的期間若需要推進某個引擎既有的輪詢才收得到結果，用引擎既有的呼叫；**找不到不改引擎其他檔案就能做到的方式時停下回報**。

### 1.3 不變的部分

L3b 的掛點位置、清除規則、`loopFramesDrawn`、`RT_DrawLayers` 不動。兩份 `XUI2DLApi.h` 這張單不改。

## 2. 插件端：全螢幕播放器在讀取迴圈中執行

L3b 停下的原因成立：M10 對迴圈內的 `UpdateLayout`／`EnsureTexture`／`ReleaseTexture` 沒有限制。裁決如下。

- `RunsDuringLoad()`：全螢幕播放器在「後端是 `XUI2DL`、讀取來源是 `xui2dl`、`cev_loadtime 1`、沒有材質綁定」時為真（L3b §2 第一條，原文不變）。後端是 `XUI2D` 時維持現狀。
- **迴圈內凍結貼圖身分**：`LoadtimeTick` 之中，全螢幕播放器（不論是否同時註冊了 Surface）不得建立、釋放或重建貼圖，也不得切換排列。做法：在 `LoadtimeTick` 進入時對這類播放器設一個「讀取中」狀態，`UpdateLayout`、`EnsureTexture`、`ReleaseTexture` 在該狀態下：
  - 目前的貼圖與下一幀相容（同尺寸、同排列）→ 照常上傳內容。
  - 不相容（串流換了解析度、排列需求改變等）→ **不上傳、不重建**，保留現有貼圖與畫面，解碼與時鐘照常前進；讀取結束後主執行緒的第一次 `Update` 照正常路徑重建並重送清單。
  - 播放器在讀取中播完（不循環）：貼圖保留到讀取結束，由主執行緒的正常路徑處理（`Ended` 事件在讀取後發一次，同 L3a 的 T7）。
- 只註冊 Surface、不是全螢幕的播放器：行為與 M10／L3a 完全相同，這張單不動它。
- `LoadtimeTick` 不得呼叫 `FullscreenOutput::Present`／`SetFrame`（L3b 原文）。讀取結束後的第一次 `UpdateAfterRender` 照既有的「內容相同就不送」規則；因為 §1.1 之後快照跨讀取保留，不需要強制重送。
- 讀取期間才開始的全螢幕播放器，要到讀取結束後才出現——寫進 `docs/design/M11-xui2dl.md` §9。

## 4. 驗證（社群版樹）

像素證據的限制同 L3b（行程外擷取在這台機器目前是全黑）。每一項註明「像素驗證」或「計數佐證」。若探測既有的 `read` 讀回能在不改 `EnginePatch/` 的前提下，於讀取結束後的第一幀取得畫面，用它驗證「讀取後畫面連續」；迴圈內的畫面不強求。
