## 對方已定的規則（XTFrame CE-117，`XUI2D_Patched` 含 512）

1. 迴圈中 XUI2D 不重播任何東西：某個 surface 要在某一圈出現，必須由 loadtime 回呼對它的 `IXUILoadFrame` 在 **LoadtimeUpdate 階段 Begin＋Submit、LoadtimeRender 階段 Execute**。階段不可錯置。
2. 同一圈只有第一個 Execute 的 screen surface 入口的 `ClearOutput` 生效；之後的入口要求清除也不清。第一個沒要求清，該圈沒人清。
3. 疊放由 loadtime 回呼的 order 決定，小的在下（Scaleform 0、貼圖來源 100、XTFrame UI 200）；`SetSurfaceOrder` 在迴圈中無作用。
4. 回呼內不得呼叫 `IXUIRenderer::Submit`、不得 Add／Remove 回呼；`IXUILoadFrame` 除 `GetStats` 與 `End` 外只能在迴圈回呼內呼叫，`End` 在主執行緒。`CreateScreenSurface`／`SetSurfaceOrder`／`WrapEngineTexture`／`GetLoadFrame` 在讀取開始前於主執行緒做完，迴圈中不建新的。
5. Wrap 的貼圖每次繪製以引擎 id 重新解析，原地更新內容會直接反映。

## 1. 要做的

- `FullscreenOutput`／`FullscreenXUI2D`：新增「迴圈繪製可用」的判斷：後端是 `XUI2D`、`XUI2D_Patched & 512`（數值自己寫，附註解說明出處，同 256 的做法）、補丁 17 的回呼可用。不可用時維持現狀（迴圈中不畫全螢幕、全螢幕播放器不在讀取中執行）；`cev_info` 的 `fullscreen backend:` 那一行加印 `loop=<0|1>`。
- 第二個 loadtime 回呼（與 M10 既有的播放器 tick 回呼分開），order **150**：
  - 登記時機照 M10 的定案（決定在鎖內、呼叫在鎖外；絕不在回呼內登記／註銷；`cev_loadtime 0` 不登記）。有全螢幕播放器且迴圈繪製可用時登記，否則註銷。
  - `LoadtimeUpdate`：以「讀取開始前最後一次主執行緒組好的圖層清單」（凍結的那一份，含 letterbox 黑邊、目的矩形、平面參數）對我方 surface 的入口 Begin＋Submit。清單在迴圈期間不變。清單為空 → 該圈不 Begin。
  - `LoadtimeRender`：該圈有 Submit 才 Execute。**一律要求 `ClearOutput`（不透明黑）**：依規則 2，前面有人畫過時不會生效，我方是第一個時才清。
  - 主執行緒在讀取結束後呼叫 `End`，之後回到平常的每幀 `Submit`。
- 播放器 tick 回呼的 order 必須小於 150（確認現值；M10 用的是對方慣例的 100 就不動）。
- 全螢幕播放器在讀取中執行的條件加上這個後端：後端 `XUI2D`、迴圈繪製可用、讀取來源 `patch17`、`cev_loadtime 1`、沒有材質綁定。**L3c §2 的「迴圈內凍結貼圖身分」原樣適用**（同一套程式，不另寫）。
- 「保留 4 幀才釋放貼圖」的既有機制：讀取期間不得釋放凍結清單引用的貼圖（讀取期間主執行緒幀數不前進，確認計數方式不會在讀取後第一幀誤放）。
- 讀取期間才開始的全螢幕播放器要到讀取結束後才出現（同 XUI2DL，已在 M11 §9；補上這個後端）。
- `docs/design/M11-xui2dl.md` §7 加一小節記下這個後端的迴圈做法與上面五條規則的出處；`CHANGELOG.md` 未發佈區段加一行。
