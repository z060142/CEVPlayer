# E2 · Video Editor 的預覽改為 Core 解碼＋一般 Qt 元件繪製（不經引擎渲染器）

依據：使用者 2026-11-19「它的影片播放，我想還是用 QT 的播放器好了，現在的作法好像會跟 CE 渲染的畫面搶 pass」；2026-11-19 的唯讀調查（下方「現況」）。模型：Opus。工作樹 `E:/coding crycry/cev-wt-e2`，分支 `e2`。引擎樹 `E:/coding crycry/CRYENGINE_Source_CEVPlayer_XTFrame`（Profile；Sandbox 的 Qt 是 5.12.3）。**不合併、不推送。**

動手前以程式核對下列前提；不符就停下回報，不自行改設計。

## 現況（調查所見，file:line 以實際程式為準）

- 預覽是 `CVideoViewport : QViewport`（`Code/Sandbox/Plugins/EditorCEVPlayer/Editor/VideoViewport.*`）：自己的 swap chain 與最小繪製管線（照 Character Tool），每個編輯器 idle 都 `Update()`（暫停時也畫），在 `SignalRender` 裡用 aux 畫棋盤格與影片貼圖（`PreviewPanel.cpp` 約 :250、:497-544）。它是一條額外的 display context，與主視口共用渲染執行緒與渲染鎖；dock 重新掛載時要整個重建視口（`VideoViewport.h:1-5`）。
- 播放器是引擎端的 `IVideoPlayer`（`PreviewSession.cpp` 約 :82，`CreatePlayer(nullptr)`），用暫存 descriptor 強制內嵌聲音路線（:82-111）；聲音由執行期模組的 SDL 裝置輸出。狀態列的寬、高、alpha、音訊、時間讀自這個播放器（`PreviewPanel.cpp` 約 :465-488）。
- `CEVPlayerCore` 已靜態連進 EditorCEVPlayer（其 CMakeLists）；`cev::PlayerCore` 提供 `Load(IByteSource)`、`Play`／`Pause`／`Seek`／`SetLoop`／`SetAvOffset`、由呼叫端驅動的 `Update()`，`FrameView` 給預乘 RGBA8（緊密、`rgbaStride`、寬高、`serial`）；Core 只輸出 PCM（`ReadAudio`／`ReadAudioResampled`），沒有音訊裝置。
- descriptor 的功能（語言的外部音檔、路線、變體選擇）在執行期模組的 `VideoPlayerImpl`／`VideoDescriptor`，不在 Core。
- 編輯器裡沒有其他功能依賴「預覽走引擎貼圖」（沒有縮圖擷取、截圖、像素讀回）。

## 要做的事

1. **新的預覽元件** `CVideoPreviewWidget : QWidget`：`paintEvent` 以 `QPainter` 畫棋盤格底，再把目前的 `FrameView` 包成 `QImage(…, QImage::Format_RGBA8888_Premultiplied)`（不複製像素；確保繪製期間該 slot 不被回收——照 Core 的 Held 語意，或在取幀時複製一份到元件自己的緩衝，擇其正確者並說明）依元件大小等比縮放繪製（`Qt::SmoothTransformation` 只在暫停時用，播放時用快速縮放）。背景選項：棋盤格／黑／白。只有新幀（`serial` 改變）、暫停時的 seek、或元件重繪事件才 `update()`——**暫停且沒有事件時不重畫**。
2. **驅動**：`QTimer`（對齊螢幕更新率或 16 ms）呼叫 Core 的 `Update()`；視窗不可見（分頁被蓋住、最小化、dock 收起）時停止計時器並暫停解碼。遊戲模式下暫停預覽的既有行為保留。
3. **聲音**：以 Qt Multimedia 的 `QAudioOutput`（pull 模式：`QIODevice::readData` 內呼叫 Core 的 `ReadAudioResampled`）輸出；時鐘用 Core 的音訊時鐘（與執行期相同的同步方式）。EditorCEVPlayer 的 CMake 加連 Sandbox Qt SDK 的 `Qt5Multimedia`（照引擎樹裡其他插件引用額外 Qt 模組的寫法；`Qt5Multimedia.dll` 已在 `bin/win_x64`）。沒有音訊裝置或初始化失敗時靜音播放並在狀態列註明。音量、靜音控制接到 `QAudioOutput`。
4. **descriptor 邏輯共用**：把「依 descriptor 決定要開哪個視訊檔（變體）、哪個音訊來源（內嵌或語言的外部音檔）、AV offset、標記點」這段從執行期模組抽成不依賴引擎的一層（放 Core 或 Core 旁的小模組，僅依賴 `IByteSource` 與 descriptor 資料結構），執行期模組與預覽都呼叫它；**執行期行為不得改變**（`cev_apitest`、`cev_flowtest`、`cev_contract_selftest`、Core 自測全過）。抽不乾淨（牽涉 CryPak、CryAudio cue 路線）的部分留在模組內，預覽只支援內嵌聲音與語言外部音檔兩種路線；cue 路線在預覽以內嵌聲音代替，狀態列註明「preview plays the embedded audio; the cue route is not auditioned here」。
5. **替換**：`PreviewPanel` 改用新元件與一個不依賴引擎播放器的 `PreviewSession`；移除 `CVideoViewport`、aux 繪製、棋盤貼圖上傳、暫存 descriptor 的做法、對 `IVideoPlayer` 的依賴。播放控制（播放／暫停／停止／拖曳時間軸／循環／逐幀步進若現有）、標記點顯示、語言與變體選擇照舊可用。狀態列的資訊改讀 Core。檔案讀取：資產在專案資料夾內（非 pak）時可用一般檔案讀取；若現行預覽支援 pak 內的檔案，沿用同一個 `IByteSource` 實作。
6. **自測**：既有的編輯器自測指令（`EditorCEVPlayerPlugin.cpp` 裡的 console 自測）更新：不再有視口計數；新增「開啟資產 → 預覽載入 → 播放 1 秒 → `serial` 前進、音訊回呼被呼叫（或回報無裝置）→ 暫停後 `paintEvent` 次數不再增加 → 關閉編輯器視窗後沒有殘留的計時器與解碼執行緒」的檢查。
