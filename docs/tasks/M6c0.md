## 要做的事

1. 讀 `docs/research/02-baseline-build.md`、`patches/README.md`、`tools/build_engine.sh`、`tools/build_baseline.sh`，以及整合樹的 `E:/coding crycry/CRYENGINE_Source_CEVPlayer_XTFrame/Tools/Integration/Build.ps1` 與 `toolset_compat.props`（VS 2022 工具組的相容設定，可參考）。
2. 把 CEVPlayer 接進社群版樹：套用社群版的註冊 patch、同步原始碼與 CMake 模組。CEVPlayer 的 SDK 需要放進引擎樹的 `Code/SDKs/CEVPlayer`——但 `Code/SDKs` 是連結、目標唯讀：**不得寫進去**。做法擇一並說明：(a) CMake 變數把 CEVPlayer SDK 路徑指到連結之外（看 `cmake/modules/CEVPlayerSDK.cmake` 是否支援覆寫）；(b) 把 `Code/SDKs` 換成一個真目錄，裡面對連結目標的每個子目錄各做一個目錄連結，再加上 `CEVPlayer`（不複製、不改目標）。做不到就停下回報。
3. 產生方案並建置所需目標（Profile）：`Sandbox`、`CryVS`、`EditorCryVS`、`CryRenderD3D11`、`CEVPlayer`、`EditorCEVPlayer`、`GameLauncher`、Resource Compiler（引擎首次執行需要）以及它們的相依。上次紀錄的失敗專案（HPiPlugin、LodGeneratorPlugin：CMakeLists 沒有呼叫 `use_xt()`；CryGameSDK：unity 重複定義；MeshImporter：缺 AssimpSDK——這次 SDK 目錄裡已有）**不在必要清單內**：它們失敗不算本單失敗，照實列出；不要為了它們修改 fork 的原始碼。引擎樹本身的原始碼原則上不改；若有擋住必要目標的編譯錯誤，列出最小的修正方案後停下回報，不自行提交到 fork。
4. 建一個最小測試專案（比照 `E:/coding3/xt-bench/cev-s0/engine/project/CEVS0.cryproject`，不依賴 GameSDK），啟動 Sandbox 與 GameLauncher 各一次：確認 `sys_SchematycPlugin` 的值讓 CryVS 載入、`CryVS.log` 產生、CEVPlayer 記錄「registered component…」之類的訊息、EnvBrowser 所需的 `EditorCryVS` 插件載入（以 log 判定）；`cev_apitest` 與 `cev_play` 一支測試素材 PASS。
5. 把重現步驟（指令、路徑、所需時間、失敗的非必要專案清單與錯誤摘要）寫成 `E:/coding3/xt-bench/cev-m6c/community-baseline.md`（主模型之後收進倉）。
