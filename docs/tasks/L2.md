## A. YUV 著色（`XUI2DL_KIND_YUV420`／`YUVA420`）

規格：XTFrame 倉 `E:/coding3/themixUI/Docs/design/23-host-integration.md` §23.aj 的「繪製」一節（唯讀）。數學上的參考：同倉 `Code/Runtime/gpu/src/planar_params.{h,cpp}`（唯讀；照規格的公式自己寫，不複製檔案）。

- `XUI2DL.cfx`：新增 technique `XUI2DLPlanar`。像素著色器對 Y、U、V（有 A 時加 A）各取樣一次（雙線性取樣器），每個平面的 uv = 畫面 uv × 縮放 ＋ 位移，再**逐平面夾在該平面矩形內縮半個 texel**；色度位置折進 U／V 的位移（`Center`：Xc = X/2、Yc = Y/2；`Left`：Xc = X/2 + 0.25、Yc = Y/2；`TopLeft`：Xc = X/2 + 0.25、Yc = Y/2 + 0.25；X、Y 是亮度的連續座標，像素 k 的中心在 k + 0.5）；一次 3×4 矩陣（含偏移）轉成 RGB，夾到 [0,1]；沒有 A 平面時 a = 1；輸出 `(rgb·a, a)`（CEVPlayer 的色彩平面是 straight），再乘頂點色。著色器不分支選矩陣或 siting。
- `XUI2DL.cpp`：每個 YUV 圖層一份常數（四個平面的縮放位移、四個箝制矩形、3×4 矩陣、有無 alpha），由圖層的 `planeY/U/V/A`、`imageWidth/Height`、`colorMatrix`、`colorRange`、`chromaSiting` 與貼圖實際尺寸在 C++ 端算好。轉換公式照 §23.aj（`Limited`：Y′ = (y − 16/255)·255/219、C = (c − 128/255)·255/224；`Full`：Y′ = y、C = c − 128/255；R = Y′ + 2(1−Kr)·Cr、B = Y′ + 2(1−Kb)·Cb、G = (Y′ − Kr·R − Kb·B)/(1−Kr−Kb)；601：Kr 0.299、Kb 0.114；709：Kr 0.2126、Kb 0.0722）。
- `src` 子矩形對 YUV 圖層同樣有效（以畫面像素計）。
- 不合法的描述（平面矩形超出貼圖、寬高為 0、`imageWidth/Height` 為 0、貼圖不是單通道 8 位元）：該圖層略過並計入 `drawsSkipped`。
- `caps` 加上 `XUI2DL_CAP_YUV`。介面結構不得改動。常數緩衝若需要第二個槽（b1），注意 XUI2D 的教訓：同一個 primitive 槽的常數緩衝階段遮罩必須固定（調查報告 B 的 CE-111）。
- `XUI2DL.cpp` 上限 900 行，超過停下回報。

## C. 探測與合規測試

`cev_probe_xui2dl` 新增子指令 `yuv <n> [scale]`：探測自己建立一張 R8 貼圖（做法照既有的 `cev_probe_r8`），以 CPU 填入合成的打包畫面，送一個 YUV 圖層；`scale` 省略時 1:1（輸出大小 = 畫面大小，左上角對齊整數像素）。同時把那張打包緩衝與參數寫到檔案（`<user folder>/xui2dl_yuv_<n>.bin` 與 `.txt`）供離線比對。

合成畫面（寬高固定、內容固定，不含亂數）至少：

| n | 內容 |
|---|---|
| 1～12 | 平滑漸層圖，2 種矩陣 × 2 種範圍 × 3 種 siting，640×360 |
| 13 | 奇數高（640×359） |
| 14 | 帶 alpha（YUVA420），alpha 為水平漸層，底下先鋪白色純色圖層 |
| 15 | 色度銳利邊緣：紅藍相鄰的直條與橫條（寬 1、2、4 像素） |
| 16 | 平面交界：Y 全 16、U 平面全 255、V 平面全 0、最右一欄與最下一列另設可辨識的值——檢查畫面最右欄與最下列沒有相鄰平面滲入 |

比對：用無損的方式取得畫面（先找既有的無損路徑：`cev_probe_loadtime` 的讀回、引擎的 tga／png 截圖；只有 jpg 可用就停下回報）。離線腳本（Python，放證據目錄）依 §23.aj 的公式以浮點算出 1:1 的參考畫面（各平面雙線性、siting 位移、箝制、矩陣、預乘、與底色混合），逐像素比對。

- **合規**：n = 1～16 在 1:1 下每個通道最大差 ≤ 1。超過就照實列出最大差、平均差、超過的像素比例與位置分佈，**不放寬門檻、不改參考**。
- **縮放**：n = 15、16 以 `scale` 2.0 與 0.75 各跑一次，只判定最右欄與最下列沒有相鄰平面的顏色滲入（與 1:1 的邊緣顏色相近），不做逐像素比對。
- **實際影片**：`cev_play_surface` 播一支 4:2:0、寬為偶數的測試素材，以契約的 hint 讓它切到打包排列（做法照既有的 `cev_bench_hint`／`cev_contract_selftest`），暫停在固定時間點，用契約快照回報的平面矩形、矩陣、範圍、siting 送 YUV 圖層；同一幀另以 `cev_allowPlanar 0` 取得 RGBA 路徑的畫面。兩張截圖的差只記錄（平均與最大），不設門檻——CPU 路徑是最近點，色邊會不同。
