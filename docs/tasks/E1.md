## 要改的項目

| # | 項目 | 現在的做法（`Code/Sandbox/Plugins/EditorCEVPlayer/`） | 改用引擎的機制 |
|---|---|---|---|
| 1 | 重新匯入 | 自己的「Reimport source」鍵與複製／轉檔流程（`Editor/InfoPanel.cpp`、`VideoEditor.cpp`）；`VideoAssetType::IsImported()` 為 false | `IsImported()`＝true、匯入時 `SetSourceFile`；`CVideoAssetImporter` 覆寫 `ReimportAsset`（**沿用存下來的匯入設定**——引擎預設實作會丟掉使用者設定，見 `AssetImporter.cpp` 的註解）；Asset Browser 的 Reimport 因此可用；面板的鍵只呼叫 `pAsset->Reimport()`。`CanAutoRepairMetadata` 維持 false。既有資產（沒有登記來源）的升級：開啟時若中繼資料裡有來源路徑就補登記並存檔 |
| 2 | 來源狀態 | 每次開啟資產都把來源檔整個算 SHA-256（`VideoImport.cpp` 的 `CheckSourceStatus`） | 平常只比來源檔的大小與修改時間（存在 `.cryasset` 的 details）；只有兩者之一變了才算雜湊確認。「原始檔，不發行」的標示保留 |

| 6 | 描述檔編輯（聲音路線、AV offset、預設語言、語言表、標記點） | 手寫 `QComboBox`／`QTableWidget`＋「Apply to descriptor (then Save)」 | `QPropertyTreeLegacy`（或本樹資產編輯器實際使用的 property tree 類別——以 stock 範例為準，例如 `EditorSubstance/PresetEditor.cpp`）＋ `SDescriptor::Serialize(Serialization::IArchive&)`；每次改動直接寫回並 `SetModified`，沒有 Apply 鍵。語言的 trigger 欄用引擎的音訊觸發器選擇器（`Serialization::AudioTrigger`，`CryCommon/CrySerialization/Decorators/ResourcesAudio.h`；選擇器由 ACE 註冊）；外部音檔欄用資源／檔案選擇器。undo：property tree 內建或 `CAssetEditor` 的機制若可直接接上就接，否則維持「沒有 undo」並在報告說明 |

## 測試與驗收

- 更新／新增編輯器自測指令（比照 `cev_editor_preview_test`）：`cev_editor_info_test`——開啟測試資產；改 AV offset 與一個標記點（經 property tree 的序列化路徑，不是直接改資料）→ 資產變 modified → 存檔 → 重新載入後值相符；語言 trigger 欄接受一個既有的觸發器名稱；`pAsset->Reimport()` 對一個來源在資產資料夾內的資產成功，且匯入設定（例如解析度／壓縮選項）與重新匯入前相同；來源檔 touch（改 mtime、內容不變）→ 狀態「需要確認」後以雜湊判定未變；來源內容改變 → 狀態「需要重新匯入」；偏好設定頁的 FFmpeg 路徑設定後 `cev_editor_ffmpeg_status` 反映、舊 JSON 的遷移一次。
- Sandbox 實跑（測試專案不載入 CryXTUI；`sys_assert_dialogues 0`）：上述自測 PASS；`cev_editor_preview_test` 仍 PASS；以 `QWidget::grab()` 存 Info 欄的 PNG（改動前後各一張）到 `E:/coding3/xt-bench/cev-e1/`。Asset Browser 右鍵是否出現 Reimport：能以程式查到該 action 可用就查，否則列為需人工確認並寫步驟。
- 執行期自測（`cev_apitest`、`cev_flowtest`、`cev_contract_selftest`）不受影響（本單不改執行期模組；若有共用檔被動到就重跑）。
