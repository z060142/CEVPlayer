## 要做的事

1. **聚合結果驅動播放器**（M6a 只記錄不作用）：每個有 Surface ID 的播放器每次 tick 取得聚合的 `visible`（任一活著的消費端可見即可見；**沒有任何消費端送過 hint 的 surface 視為可見**）、最大像素高度、`acceptLayouts`（本單不使用，M8 用）。全螢幕與材質輸出、沒有 Surface ID 的播放器恆為可見。播放器選項 `PauseDecodeWhenHidden`（預設開；描述表新增 `SetPauseDecodeWhenHidden`／查詢，FlowGraph 的 `VideoAdvanced:Settings` 與 `VideoUI:PlayToSurface`、Schematyc 元件、CryVS 對應函式各補一個埠／屬性——CryVS 只改原始碼並保持與表一致，本單無法在這棵樹編譯它，報告註明）。
2. **看不見時的兩段行為**（Core：`Core/src/PlayerCore.cpp` 的 worker `VideoStep` 與 seek 的 skip 模式；時鐘與聲音照走）：
   - 不可見的當下起：視訊改為「只解碼」——不取 ring slot、不複製平面、不轉色、不上傳（沿用 seek 時的 skip 路徑）；`contentSerial` 不動。
   - 連續不可見超過 `cev_hiddenStopSeconds`（預設 2.0；0＝永不完全停止）：停止視訊解碼（不再餵封包）。
   - 重新可見：從「當下時鐘時間」的前一個關鍵幀以 skip 模式補解到當下，再恢復正常輸出；補解期間維持顯示最後一張已上傳的畫面。記錄補解耗時（`cev_stats` 新欄位）與補解的幀數。只經過第一段（未完全停止）就恢復時不需要找關鍵幀，直接恢復輸出。
   - 以時間計的門檻用播放器自己的時鐘或呼叫者給的 dt 累計，不讀引擎計時器（M6a 的規則）。
3. **結尾與循環的判定不依賴視訊解碼器到達 EOF**：以時鐘與 duration 判定（今天要 `VideoAtEnd() && ring.ReadyCount()==0`，否則等寬限期——`PlayerCore.cpp` 約 :878-895）；不可見時 `Ended`／`Looped`／標記點事件的時刻與可見時一致（誤差在一個 tick 內）。可見時的行為不得退步（最後一幀仍要顯示出來）。
4. **開始播放時依像素高度選變體**（`VideoPlayerImpl::PickVariantPath` 與 Core 的 `PickDescriptorVariant`）：`Play`（從 Stopped／Ended）與 `open` 時，若聚合的像素高度 > 0，取「高度不小於它的最小變體」，否則主影片；強制變體（`SetVariant`、`cev_variant`）優先；全螢幕維持現行依視窗高度的規則。播放中不自動切換。循環回到開頭時不重新選（避免聲音中斷）。
5. **契約 v2 的其餘部分**（`Module/Contract/TexSource.cpp`）：
   - `open(name, src, options)`：0＝不接（非 `.webm`／`.cevvideo` 的副檔名、容器辨識失敗、插件已關閉）；1＝建立了一個由這次 `open` 擁有的 surface 播放器（非阻塞：函式內只做副檔名與既有登錄的檢查並排入佇列，實際載入在下一次 tick；`state`＝loading；之後失敗以 `state`＝error＋`errorCode`）；2＝同名 surface 已存在且不是由 `open` 擁有（關卡邏輯建立）。同一個名字重複 `open`：已由 `open` 擁有時，`src` 相同回 1（不重開）、不同則換片並回 1。`options` 的 autoplay／loop／muted／volume 套用。
   - `close(name)`：只銷毀由 `open` 擁有的；其他不動。
   - `control(name, verb, value)`：PLAY、PAUSE、SEEK、RATE、LOOP、VOLUME、MUTE——排入佇列於下一次 tick 套用；回 1＝接受排入，0＝名字不存在、插件已關閉、或值超出範圍（RATE 超出 Core 的範圍、SEEK 為負／非有限值）。`state`＝loading 時的 SEEK 記住，載入完成後套用。對關卡邏輯擁有的 surface 也可 `control`（意圖；播放器照做）。
   - 快照補齊：`state` 六種狀態、`errorCode`、`timeSeconds`、`durationSeconds`、`loopCount`（每次回繞＋1）；確認 `flags` bit2（playing）正確。
   - 規則 10 維持：契約函式內沒有引擎呼叫；佇列與快照同一把鎖或無鎖結構，函式可由任何單一執行緒呼叫。
6. **匯入轉碼的關鍵幀間隔**（`Core/offline/src/ffmpeg/FfmpegCommands.cpp`）：VP9／VP8 編碼加 `-g <幀率 × 2 秒，四捨五入，至少 1>`（幀率未知時 60）與 `-keyint_min` 相同值不必加；變體與重新壓縮同樣適用。Editor 的串流資訊若已有探測資料，顯示「最大關鍵幀間隔」；超過 5 秒時在 Info 欄顯示一行提示（看不見後恢復可能卡頓，建議重新壓縮）。探測不到就不顯示。`cevffmpeg_selftest`／`cevoffline_selftest` 更新。
7. **量測**：`cev_stats` 與 `cev_stats_file` 增加：可見狀態（visible／decode-only／stopped）、補解耗時與幀數、選用的變體、聚合的像素高度。

## 測試

- `cev_contract_selftest` 擴充（自測以 `GetProcAddress` 取得匯出並扮演一到兩個消費端）：
  - 沒送過 hint → 視為可見，行為與今天相同。
  - 一個消費端 visible＝0：下一個 tick 起 `contentSerial` 不動、`cev_stats` 的複製／轉色／上傳位元組為 0、解碼仍在；超過門檻後解碼為 0（把 `cev_hiddenStopSeconds` 設小以縮短測試）；visible＝1 後 `contentSerial` 恢復遞增，補解耗時有值且幀數 ≤ 關鍵幀間隔的幀數；恢復後的畫面時間與時鐘一致（誤差 ≤ 2 幀）。
  - 兩個消費端一個可見一個不可見 → 可見；可見者 `release` 後 → 不可見；120 次更新淘汰同理。
  - 不可見期間：非循環影片在時鐘到達 duration 時進入 ended、`Ended` 事件送出一次；循環影片 `loopCount` 遞增、`Looped` 事件照送；標記點事件照送。
  - `PauseDecodeWhenHidden`＝off → 不可見時照常解碼與上傳。
  - 變體：以 `tools/test_descriptors/variant_test.cevvideo`（或自建含 360／720／1080 三個變體的描述檔）——hint 像素高度 300 → 360 的變體；700 → 720；0／沒 hint → 主影片；強制變體優先。
  - `open`：回 1 且立即返回（量函式耗時 < 1 ms）、`state` 由 loading 轉 ready／playing；不存在的檔 → 回 1 後 `state`＝error；錯誤副檔名 → 0；關卡邏輯已建同名 → 2 且 `close` 不影響它；重複 `open` 同 src → 1 不重開；不同 src → 換片（`generation`＋1）。`close` 後 `query` 回 0。
  - `control`：每個 verb 的效果由快照驗證（SEEK 後 `timeSeconds`、PAUSE 後 `state`、LOOP＋`loopCount`…）；loading 時的 SEEK 被記住；超出範圍回 0。
- Core 自測新增：看不見的兩段行為與恢復（不經引擎）、結尾判定、`PickDescriptorVariant` 的像素高度路徑。既有 Core 自測的那一項已知失敗（`av_sync_flash_beep`／`flashOk`）若仍在：查出是素材（FFmpeg 版本）還是程式的問題並回報，不要略過。
- `cev_apitest`、`cev_flowtest` 更新並全過（項目數會變，報告新數字）；`tools/smoke_test.sh` 過。
- 引擎內量測（GameLauncher，測試專案不載入 CryXTUI）：1080p30 素材（關鍵幀 2 秒）以 surface 播放，自測扮演消費端切換可見性，`cev_stats_file` 記錄三種狀態下的解碼／複製／轉色／上傳耗時與位元組，以及 10 次恢復的補解耗時分佈；另以 `vp9_alpha.webm`（全片只有一個關鍵幀）示範最壞情況的補解耗時。數字進報告。
